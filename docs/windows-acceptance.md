# Native-channel acceptance (not yet run)

Run only after the operator explicitly authorizes deployment/restart and has confirmed the state of any real training work. This checklist is not an instruction to interrupt the current Windows session. Use a dedicated test workspace/channel and disposable long-running fixture, not a real training job. Keep credentials private.

1. Record OMP 18.10.4, runtime, extension commit and loaded entry. Startup/restart/session switch must be off, with no Slack connection before `/slack`.
2. Enable in the intended main conversation. Verify an authorized owner mention and DM receive replies in their original threads, using existing model/tools/approval settings. The main transcript is intentionally shared; do not test with unrelated private secrets or claim per-channel context isolation.
3. While a harmless long-running local fixture owns the session, send ordinary text and `!queue TEXT` from two channel threads and a DM. Confirm they appear in OMP's native follow-up queue immediately, not a plugin FIFO. In native one-at-a-time mode, check FIFO consumption and individual reply destinations before global idle. Also test two threads in the same channel/DM.
4. During a disposable pure `wait`, send `!insert TEXT` and `!steer TEXT` from the owner and an already-approved dot/bot/member channel identity. Confirm native steering admission and intervention. Confirm unrelated background work stays alive. Check the fixture's PID/heartbeat independently; a Slack reply or status count does not prove training is running. For an ordinary noninterruptible tool, delayed insertion is acceptable; do not promise instant interruption.
5. Send `!status` while model work is blocked and while outstanding work is full. It must bypass the model, return scoped counts/activity only, and not disclose other source IDs, text or tool arguments. Unauthorized users, unauthorized DMs/workspaces and duplicate event deliveries must not prompt or receive status. Empty insertion/queue commands should return usage only.
6. Exercise two-source insertion, native all-mode batching, model `pause_turn`, error recovery and a nonterminal maintenance continuation. Combined final text must never be broadcast to a guessed route. Use explicit consumed `request_id` with `slack_reply` for each desired source reply. Pending/retired IDs must be rejected. The conservative late-queue-arrival race can require explicit replies too.
7. Test a native model-reference rewrite such as a `^provider/model` mention using a valid configured model. Confirm the fixed request header still associates consumption and replies. A marker merely quoted in the user body, an unknown ID or altered fixed header must not claim another request.
8. With local and Slack pending items in both native lanes, run `/slack off`. Only still-editable plugin pending items should be removed; include a follow-up promoted in the TUI. Local queue items/work must remain. The command must warn that admitted/preflight/claimed work may continue, and later Slack tools/results must be blocked. Verify no main-session abort occurred. Off cannot recall Slack writes already submitted.
9. Test off while idle preflight is waiting, off after live steering is claimed, disconnect, repeated enable, takeover and delayed socket callbacks. Confirm no replay and no stale reply permission. A takeover may leave admitted work running in the old conversation, but must revoke its old reply route before enabling the new owner.
10. Switch/branch/navigate to a different session with old pending/preflight records. Verify the old records never execute in the new session. Old routes must be revoked and the new session remain off until manually enabled. Never bypass an unconfirmed old listener shutdown.
11. If testing files, use explicitly requested harmless output/input files and the already-authorized Slack scopes. Verify immutable source thread, file limits, no overwrite on download, inherited OMP approval, off between upload phases, and no blind retry on uncertain mutation outcomes. No token/configuration changes are required by this revision.
12. Record pass/fail, exact commit/runtime and redacted fixed error categories. Do not upload environment dumps, tokens, private transcripts or production messages as fixtures.

Current revision: typechecked and tested in the cloud with protocol fakes and existing Slack SDK/IPC regression tests. No live Slack/model/native-wait/Windows acceptance or real training-process survival is claimed.
